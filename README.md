# דיוק — מבדקים במאמרי חסידות

אתר סטטי בעברית ובכיווניות RTL ללימוד מדויק בתורה אור וליקוטי תורה.
בגרסה הראשונה מופיע מבדק בן ארבע שאלות על ״השמים כסאי״.

**כל התוכן הוא טיוטה לבדיקה, לא בנק שאלות מאושר.** המבדק מבוסס על טקסט
שסופק לצורך העבודה. הספר, הפרשה והעמודים טרם אומתו; סוף הטקסט שסופק
קטוע ואינו נבחן. אין להוסיף מיקום משוער או לאשר תוכן ללא בדיקה.

## חוויית המבדק

- שאלות ניתוח והערכה המעוגנות במילים, בהקשר ובמהלך של המאמר.
- בחירת ביאור, לאחריה בחירת ראיה, ורק לאחר שליחת שניהם נחשף המשוב.
- ביאור וראיה נבדקים בנפרד. כתיבת הסבר היא רשות ומוערכת רק באופן עצמי.
- משוב עם עוגן במקור, סיכום לפי מרכיבים ומבדק חוזר על שאלות לחזרה.
- אין להסיק שליטה במאמר מציון בניסיון יחיד.

## הפעלה

אין תלויות התקנה או שלב בנייה. נדרשים שרת קבצים מקומי ו־Node לבדיקות בלבד:

```sh
npm run serve
# http://127.0.0.1:4173
npm test
```

אין לפתוח ישירות כ־`file://`; האתר טוען את בנק השאלות באמצעות `fetch`.
ב־GitHub Pages מפרסמים מהענף `main`, תיקיית השורש. קובץ `.nojekyll`
מונע עיבוד Jekyll; כל הקישורים המקומיים יחסיים ומתאימים לכתובת פרויקט.

## נתונים ופרטיות

האתר אינו שולח תשובות לשרת ואין בו אנליטיקה. ההתקדמות נשמרת ב־localStorage,
כולל הניסיון הפעיל ו־30 הניסיונות האחרונים. היא אינה מסתנכרנת בין מכשירים
ועלולה להימחק בניקוי הדפדפן. התשובות שנבחרו נשמרות לאחר שליחת השאלה;
טקסט והבחירות שטרם נשלחו אינם נשמרים.

ניתן לייצא ולייבא גיבוי JSON. גיבוי כולל הסברים אישיים ולכן יש לשמור אותו
במקום פרטי. ייבוא מחליף את ההתקדמות לאחר אישור מפורש ובדיקת מבנה, מזהים
וגרסת תוכן. גיבוי לא תקין אינו מחליף נתונים. נתונים מקומיים לא קריאים אינם
נדרסים אוטומטית, וניתן לייצא אותם לשחזור או למחוק במפורש.

האתר אינו טוען שירותים חיצוניים אוטומטית. קישור למאמר המקור נפתח רק
לבקשת המשתמש. קוד האתר ומפתחות התשובות ציבוריים: זהו כלי לבדיקה עצמית,
לא מערכת למבחנים מאובטחים או להסמכה.

## עריכת תוכן

בנק השאלות נמצא ב־`questions.json`. לכל שאלה מזהה קבוע, מיומנות, תהליך
חשיבה, עוגן במקור, אפשרויות עם הסברים, ראיה מכריעה, תשובה ומחוון.
`correctOption` ו־`correctEvidence` מפנים למזהי האפשרויות, לא למיקומן;
הסדר בתצוגה משתנה כדי לא לעודד בחירה לפי מיקום.

לאחר שינוי שמשנה משמעות, מפתח תשובה או מחוון, יש להעלות את `revision`.
האתר לא יערבב התקדמות מגרסאות תוכן שונות; יש לייצא את הנתונים הקודמים
לפני מחיקה. לשינוי קוסמטי בלבד אין צורך להעלות גרסה.

סטטוס `draft` נשאר גלוי באתר עד שבעל התוכן בודק ומאשר את כל הבנק.
רק לאחר מכן ניתן לשנות את `reviewStatus` ל־`approved`.

עיקרון הבדיקה: ביאור נכון בכלל אינו בהכרח מבוסס במאמר הזה. יש להבחין בין
טענה מפורשת, מסקנה נתמכת, תוספת לא מבוססת וסתירה; לא להמיר ״לא כתוב כאן״
ב״שגוי תמיד״. מקבלים ניסוח עצמאי מדויק, ולא דורשים העתקה מילולית.
